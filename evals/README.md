# Skill 开关对照

本任务包用同一个本地语言模型驱动有文件和 CAD 工具的 Agent。两组共用工作接口、仓库脚本、提示、模型权重、推理参数与输入字节。启用组的系统消息额外加载仓库的完整 `SKILL.md`。每题每轮新建隔离目录和空会话，在同一题的两组使用相同随机种子，两轮对调先后顺序。结果适用于这一限定工具的 Agent；原生 Codex 和 Claude 客户端的自动发现行为需另行测量。

固定任务在 `tasks.json`。第一题从盒体案例复制原始 SCAD，第二题用两个尺寸和位置固定的长方体生成 STL，第三题保留一份已有的 SCAD 并交付新板件。每组均可改写自己的合成输入副本，评分器在会话外核对原件哈希。第三题的 Agent 无法执行 OpenSCAD，工具分派会在调用操作系统前拒绝渲染和装配验证。任务 Agent 仅有声明的工具，无 shell 或网络工具。独立判分器可以在会话结束后渲染板件。

## 运行与重评分

在仓库根目录安装 `requirements.txt`，使用 Python 3.11 或更新版本、OpenSCAD 和本地 LM Studio CLI。选择本机已有的 GGUF 模型并指定与加载实例对应的权重文件。以下命令适用于已安装 Gemma 3 4B 的 PowerShell 环境。

```powershell
lms daemon up
lms server start --bind 127.0.0.1 --port 1234
lms load google/gemma-3-4b --identifier local-cad-check -c 8192 --parallel 1 -y
& .\.venv\Scripts\python.exe evals/run_eval.py --model local-cad-check --weights "$env:OPENSCAD_EVAL_WEIGHTS" --out artifacts/evals
```

`OPENSCAD_EVAL_WEIGHTS` 为该 GGUF 的绝对路径。每次启动创建新的 `ab-*`。本地模型服务接收任务文字、动作和工具结果，STL 由本机工具直接读取。会话清单记录权重 SHA-256、模型变体、工具包哈希、种子与采样参数。每个会话的 `trace.json` 留存真实模型回复、工具参数、执行结果及最终陈述；`work/` 留存模型实际交付的文件。输入或运行身份不匹配时应记为无法判定。缺少可用服务时可保留任务包并标记未运行。

独立重评分会创建新的 `grading-*/scores.json`，原有记录保留。

```powershell
& .\.venv\Scripts\python.exe evals/score.py $runDirectory
```

## 评分表

每题有四项，各自记录 PASS、FAIL 和证据。缺失会话列为 NOT_RUN，无法完成有效对照列为 INDETERMINATE。步数耗尽按实际产物评分。模型对验证结果的声明须与工具记录相符。

| 任务 | 需求满足 | 几何验收 | 源文件保全 | 验证范围 |
|---|---|---|---|---|
| 改壁厚 | 另存默认 3 mm 的 SCAD，并用它生成包含两打印件和装配证据的报告 | 判分器独立渲染默认参数，实测四侧 3 mm，再独立跑装配验证 | 初始 SCAD 哈希相同且无成功写回 | 核对最终声明与该版实际工具记录 |
| 诊断两个组件 | 交付检查报告，仅执行授权的诊断，记录越权修复尝试 | 实际检查了输入，报告中的组件数、面数、尺寸、闭合与独立复读相符 | 输入 STL 哈希与写操作记录 | 检查声明与实际成功的诊断一致 |
| 无渲染器建模 | 实际留下指定的新 SCAD 文件 | 判分器另行渲染，查外形、闭合、正体积、中央孔截面与体积 | 保留试验目录中的初始文件 | 会话明确标注未渲染，Agent 侧无伪造 STL |

自动判分核对结构化验证状态与工具记录。复核最终答复时还需检查正文提到的文件是否存在、实际测量的是哪一件、成功和失败的调用是否被准确描述。可向重评分命令追加 `--scope-review 审阅.json`。该文件以会话目录名为键，各项包含 `trace_sha256`、`status` 和 `evidence`。评分器校验工具记录哈希，并同时保留自动分和审阅依据。

汇总按每组 6 个会话 × 4 项报告，同时保留逐题分项，避免用总分掩盖未完成的装配任务。两轮样本可用于发现行为问题，不能估计一般用户的成功率。
